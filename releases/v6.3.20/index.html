Public Address And Private Key

Node-only

A standalone node does not need a mining wallet or private key. It can sync, serve peers, and expose local dashboard status.

Pool mode

The pool needs your public payout/mining address. Production block submission/payout operation also needs the matching pool operator private key.

Never paste a private key into public chat, screenshots, Git commits, shell history, or dashboard fields. Prefer the installer hidden prompt, a local secret manager, or an environment variable set only in the current terminal.

Why restore first?

A fresh node can sync from peers, but restoring the rawdatadir archive first avoids reprocessing most of the chain. After extraction, the node still performs normal BlockDAG consensus validation and P2P handshakes while catching up recent blocks.

Do not copy private node identity files between machines. This release data archive is intended as public chain data, not a wallet or node identity backup.

Dashboard And Ports

Dashboard

Open http://localhost:8088 on the host or http://<pool-host-lan-ip>:8088 from the LAN. Use it to watch sync status, miner lanes, earnings, warnings, and live operational state.

Local APIs

Collector status is on http://localhost:9280/api/status. Chain RPC is 38131, EVM HTTP is 18545, and Stratum is 3334.

Security

Expose only P2P TCP 8150 to the internet. Keep dashboard, Stratum, collector, chain RPC, EVM RPC, and database ports on localhost or trusted LAN/VPN.

ASIC Miner Setup

Find the ASIC IP on Ubuntu

ip -4 addr
ip neigh
sudo apt-get install -y arp-scan nmap avahi-utils
sudo arp-scan --localnet
sudo nmap -sn 192.168.1.0/24
avahi-browse -art | less

Also check your router DHCP leases. Match the device by MAC address, vendor string, hostname, or by unplugging/replugging one miner and watching which lease changes.

Configure X30 / BlockDAG ASIC style firmware

  1. Open the miner IP in a browser and log in.
  2. Go to Mining, Pool, or Miner Configuration.
  3. Set Pool 1 URL to stratum+tcp://<pool-host-lan-ip>:3334.
  4. Set Worker/User to your public payout wallet. If worker suffixes are supported, use 0xYOUR_PUBLIC_ADDRESS.worker1.
  5. Set Password to x unless your firmware requires something else.
  6. Save/apply and reboot only if the firmware asks.
  7. Watch the dashboard Miners/Earnings views for the ASIC MAC address and accepted shares.
Do not expose Stratum to the internet by default. Keep ASICs and the pool on the same LAN or a private routed network.

Router P2P Port Forward

  1. Give the node/pool host a reserved DHCP address, for example 192.168.1.50.
  2. In the router, forward external TCP 8150 to that LAN IP on TCP 8150.
  3. On Ubuntu, allow the port if UFW is enabled: sudo ufw allow 8150/tcp.
  4. Restart the stack or node after changing public IP/router configuration.
  5. Verify from outside the LAN, not from the same Wi-Fi: nc -vz YOUR_PUBLIC_IP 8150 or a port-check website.

If your ISP uses CGNAT, inbound P2P forwarding will not work until you get a public IPv4, IPv6 path, VPN relay, or hosting provider with forwarded ports. Outbound sync can still work without public inbound discovery.

Help And Troubleshooting

What should I install first?

Install node-only if you only want to sync and support the network. Install pool mode if ASIC miners will point at this host. For a real pool, restore the chain data before first start.

How do I know sync is working?

Open the dashboard on port 8088 or check curl -s http://127.0.0.1:9280/api/status | python3 -m json.tool. Look for sync status, percent, remaining blocks, warnings, and whether mining gates are open.

The dashboard says syncing or catch-up pause. Is that bad?

No. It means the stack is preventing unsafe mining while the node catches up. Pool mining should only accept/submit once sync and peer freshness gates pass.

No peers or very slow sync.

Check outbound internet, DNS, system time, and that TCP 8150 is not blocked. Add the BOOTSTRAP_PEER_ADDRESSES value from this page to .env, restart the node, and watch logs with docker compose logs -f node.

ASIC is not visible on the dashboard.

Verify the ASIC pool URL is exactly stratum+tcp://<pool-host-lan-ip>:3334, not a Docker 172.* address. Confirm the ASIC and pool are on a routed LAN, and run sudo arp-scan --localnet or sudo nmap -sn <lan-cidr> to find the miner.

Docker permission denied.

Log out/in after adding your user to the docker group, or run the installer from a terminal where passwordless sudo can run Docker. Check docker compose version and docker info.

Port already in use.

Another stack may already be running. Check ss -ltnp | grep -E '(:3334|:8088|:9280|:8150|:38131|:18545)'. Stop the old stack or change the corresponding host port in .env.

IPFS gateway is slow.

Try another gateway, use local Kubo, or run ipfs get /ipfs/bafybeieyhcnszf7ksylee5dsdktkdgm5q45fiuaqjrqxmfsbksafs3crny. Always verify the SHA256 after download.

Where are logs?

Use docker compose logs -f node, docker compose logs -f pool, and docker compose logs -f dashboard from the extracted release folder. Runtime files are under ops/runtime.

Can I delete the downloaded archive after extraction?

Yes, after the stack has started and you have verified the hash/extraction. Keeping it is useful if you expect to reinstall soon.

What should I never publish?

Private keys, generated .env, node.conf if it contains secrets, node identity keys, keystores, database dumps with private data, and ASIC admin credentials.
