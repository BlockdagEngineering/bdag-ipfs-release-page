Public Address And Private Key

Node-only

No wallet or private key is required. Restore chain data, start the node, and use the dashboard for sync status.

Pool mode

Requires your public payout/mining address. Production block submission/payout operation also needs the matching private key. Enter private keys only through the hidden prompt or a secure local environment; never paste them into public chat or commit them.

This is now the default install path. It avoids wasting time on a long fresh sync and makes architecture mismatch obvious before large downloads.

Restore behavior

The archive is a zstd tar containing public mainnet raw chain data. Extract it into data/node/mainnet, then the node catches up recent blocks from peers and validates normally through consensus.

Do not copy private node identity, wallets, keystores, or generated .env files between machines.

Find ASIC IPs

sudo arp-scan --localnet
sudo nmap -sn 192.168.1.0/24

Configure miner

  1. Open the ASIC web UI.
  2. Set pool URL to stratum+tcp://<pool-host-lan-ip>:3334.
  3. Set user/worker to your public payout address, optionally with a worker suffix.
  4. Set password to x unless firmware requires another value.
  5. Save and watch the dashboard Miners/Earnings views.

Help

Why is there no sync-only shortcut?

The previous shortcut let users download the stack without restoring chain data first. The recommended path is now restore-first because it is faster and catches architecture issues before startup.

What if I am on x86_64?

Use the linux-amd64 payload. The architecture helper now selects it automatically.

What if the installer says payload mismatch?

You downloaded the wrong architecture for the host. Download the matching payload. Use BDAG_ALLOW_CROSS_ARCH_PAYLOAD=1 only when you intentionally configured Docker CPU emulation.

How do I know it worked?

Check curl -s http://127.0.0.1:9280/api/status | python3 -m json.tool, dashboard port 8088, sync status synced, remaining blocks 0, and ASIC accepted shares.
