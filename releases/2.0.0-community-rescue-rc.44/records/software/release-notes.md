RC44 is the public-RPC maintenance, profiler, transactional-handoff, and cross-architecture package-qualification hardened canonical-continuation recovery candidate. It retains the exact live-proven corechain, pool, and dashboard revisions from RC39/RC41. Signed dataset policy, live historical boundaries, the governed checkpoint, the post-divergence continuation commitments, and the required fresh-peer floor remain mandatory. Mining profiles always wait for producer-safe currentness before activation.

RC44 moves all dataset authentication, cold validation, continuation, capacity, package, and image checks ahead of its sole disruptive boundary. Candidate activation preserves the active data path, retains the original host-controller receipt through handoff, commits the project root only after durable boot passes, and restores the prior root, configuration, unit enablement, and controller services after a failed candidate. It rejects recovery states that could rename active data, validates restored direct-root bindings, and recontains a partial rollback restart into a controlled stop.

RC44 supersedes unpublished RC43 after independent readback exposed a cross-built package-smoke harness gap. The signed RC43 AMD64 and ARM64 payloads, release locks, architectures, and metadata were valid, but an AMD64 package runner modeled its own architecture while smoke-testing the ARM64 archive. RC44 derives the write-only smoke target from the signed payload metadata, rejects unknown platforms, and requires a fresh extraction and installer smoke for every finished package matrix target before upload.

The pinned core profiler ignores its configured bind address and opens wildcard port 1234. RC44 therefore omits profile= from all generated node configs and release validation rejects its reintroduction. Native metrics remain enabled. Operators upgrading an older live-proven node should keep the profiler blocked from non-loopback access until the RC44-generated config is active.

Public-RPC qualification is packaged as a non-authoritative health observer. It requires a fresh committed head, fresh compatible consensus peers, archive evidence, capacity, and canonical agreement; it never treats an explorer or configured witness as mining authority. A native transport timeout may preserve only the byte-exact last-certified EVM commitment for at most 30 seconds before the existing bounded explicit HTTP 503 maintenance mode. Neither mode refreshes the certificate or grants mining authority. Changed commitments, generic failures, expiry, archive failure, and storage failure withdraw readiness. The disqualified v26 archive is rejected explicitly. Fresh restores must use an authenticated dataset after the historical exclusion; portable v27 is the qualified recovery dataset. A signature authenticates distribution but never defines chain truth.

Portable v27 is not a historical full-archive dataset. Archive mode retains all state from its imported boundary forward; full-archive mode still requires an independently qualified archive-equivalent dataset. Public RPC requires an independently configured edge proxy, TLS, abuse controls, monitoring, and restart recovery.

Protocol 46 compatibility remains the live-proven emergency boundary.
