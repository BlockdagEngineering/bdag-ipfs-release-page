# BlockDAG Community Rescue RC62 — Human Install Guide

Release `2.0.0-community-rescue-rc.62`, sequence `62`, is a software-only
installer correction for mainnet chain ID `1404`.

Install only while the page status is **Published** and its signed package
hashes, sizes, immutable CIDs, release key, signed records, and publication
timestamp all validate. Stop if any field is absent or mismatched.

## What RC62 changes

- Mining-profile staging now loads the signed digest for
  `ops/local_chain_attestation.py`.
- The signed digest loader and the privileged profile file list must contain
  exactly the same files.
- `bdag-local-peers.service` uses the signed
  `/usr/local/sbin/bdag-local-peers` wrapper and the installer-owned active
  project-root record. It no longer embeds a retired release directory.
- An interrupted upgrade can use an authenticated `adopted_from` runtime only
  after both releases verify and their Compose project, node-data directory,
  release lock, chain, fork, and checkpoint identities match.
- Authenticated recovery preserves the exact profile-activation failure status
  while retaining its guarded rollback and diagnostic output.
- Candidate and authenticated prior-runtime repair locks use independent
  private FIFOs instead of concurrent Bash coprocesses. Successful controller
  rollback returns an explicit status, making the path deterministic on the
  Bash 5.2 version used by the protected Ubuntu runner.
- Changed locks, mismatched identities, unsafe paths, symlinks, and arbitrary
  custom `bdag-*` controller units still fail closed before service mutation.
- The RC58 arbitrary-precision coinbase accounting correction is retained.
- Consensus, chain ID, P2P rules, block production, and miner eligibility are
  unchanged.

RC58 and RC59 remain immutable. RC60 and RC61 failed protected preflight and
are not published. RC62 is a new signed sequence rather than an in-place
modification of an earlier release or reuse of either failed candidate.

## Before installation

1. Confirm the manifest pins:
   - stack `60c3c6fd66edf24f79aff8ae8e0f91a3d01adb2e`
   - corechain `bb0f7a6fed918e56251aa602503c90f1e1f30cb8`
   - pool `79001ae94a6d66f1ef0614ef0b78e79fdf3b0f50`
   - dashboard `f00b654f79e50346bf6e866348cf07bdcb3b44ec`
2. Verify the final SHA-256, byte count, release authorization signature,
   release-key DER fingerprint, signed sequence `62`, and immutable CID.
3. Back up Postgres and retain compatible node data, `.env`, and node identity.
4. Rename custom systemd units that use the reserved `bdag-*` namespace.
5. Never edit the signed package or bypass its integrity checks.

RC62 publishes no portable or full-archive dataset. Use **Keep / sync** to
preserve compatible data or synchronize normally. Never combine database or
freezer directories from different histories.

## Installation

Use the command generated by the published page. It downloads the release
authentication manifest, verifies its detached signature and release-key DER
fingerprint, authenticates the selected architecture package, extracts it, and
runs the packaged installer.

Fresh installation defaults to sync-only/no-miner. Select the mining profile
only when the host is intended to run a pool and provide only the public
coinbase address. Never provide a seed phrase or wallet private key.

## Verification

After installation:

1. Confirm the installer reports sequence `62` and the expected four source
   commits.
2. Confirm chain ID `0x57c`, advancing native/EVM heads, fresh peers, and no
   quarantine or controlled-stop marker.
3. Confirm existing node data and Postgres volumes were preserved.
4. On a mining host, verify the first accepted block keeps the complete
   node-issued reward through pool accounting. A normal regression vector is
   `23,983,626,033` atomic units, or exactly `239.83626033 BDAG` gross.
5. If installation fails, retain the transaction journal and use the
   authenticated rollback/recovery output. Do not delete data or patch signed
   files by hand.
