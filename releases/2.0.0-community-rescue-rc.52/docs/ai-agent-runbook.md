## Scope

RC52 fixes one accounting fault. The pool previously converted the node's
1e8-unit reward to Wei in `uint64`; the correct mainnet value exceeds
`math.MaxUint64` and wrapped. RC52 uses arbitrary-precision integers from
conversion through the configured fee, PPLNS allocation, Postgres, and wallet
payout.

Do not describe this as a new subsidy. RC52 does not modify consensus reward
calculation, header validation, staking distribution, miner-access policy,
pool fee, PPLNS policy, or maturity settings. Stack, corechain, and dashboard
are the exact RC44 revisions; only the pool revision advances.

## Safety Rules

1. Never request a seed phrase, private key, node identity key, database
   password, or RPC credential.
2. Inventory and preserve the pool database and chain data before changes.
3. Record the last pre-upgrade block, credits, and payouts.
4. Pause automated payouts until a post-upgrade block is reconciled.
5. Verify the release signature, key fingerprint, sequence, package SHA-256,
   and architecture before installation.
6. Do not restore or merge chain database directories for this software-only
   update.
7. Do not rewrite historical reward or credit rows in place.
8. Stop on a signature, chain ID, checkpoint, canonical history, balance, or
   reward-breakdown mismatch.

## Installation

Use the command generated by the release page. Require absolute paths, a
non-root runtime account, Docker Engine, Docker Compose v2, and enough space
for the package, extraction, and rollback copy.

For mining, collect only:

- the public `0x...` payout address.

The generated command must fetch signed records from
`records_delivery.cid`, download the selected package by immutable CID, force
IPv4 and HTTP/1.1, verify SHA-256 and signatures, and invoke the installer from
the verified package.

Then wait for one accepted, mature block and compare:

- expected Wei value using arbitrary-precision multiplication by `10^10`;
- transaction fees;
- `blocks.reward`;
- configured pool fee and `blocks.fees`;
- PPLNS snapshot and credits;
- actual spendable coinbase/staking receipt;
- any payout transaction.

## Historical Rows

RC52 intentionally leaves prior rows unchanged. A safe historical repair
requires canonical block headers, per-block transaction fees, PPLNS snapshots,
payment history, and actual coinbase/staking receipts. Produce a separate
reconciliation report and preview before any credit or payment mutation.

On failure, preserve evidence, stop restart/payment pressure, and report the
signed release identity plus redacted logs. Never weaken signature, chain,
ownership, or accounting checks to make the upgrade proceed.
