BlockDAG Community Rescue

BlockDAG 2.0.0-community-rescue-rc.52

A focused mainnet pool correction for chain ID 1404. RC52 restores the complete node-issued coinbase reward through pool crediting and payout without changing the consensus subsidy schedule.

Coinbase accounting restored. Future accepted blocks retain the full reward value. Existing under-credited ledger rows are preserved and require a separate operator reconciliation.

What RC52 fixes

The previous pool converted the valid 1e8-unit node reward to Wei inside a 64-bit integer. Normal mainnet rewards exceed that range, so the ledger retained only the wrapped remainder.

Full reward precisionReward conversion, the 1% pool fee, PPLNS credits, Postgres values, and wallet payouts now remain exact above the 64-bit limit.
Everything else unchangedRC52 keeps the RC44 stack, core, dashboard, subsidy policy, miner-access policy, pool fee, and maturity settings. Only pool reward accounting advances.
Forward correctionNew accepted blocks are credited correctly. Historical wrapped credits are not silently rewritten or paid twice.

Verify before installing

A successful download is not enough. Verify the exact bytes and the signed trust records.

Software

  1. Match the package SHA-256 to the release manifest.
  2. Verify the release authorization signature with the published release key.
  3. Confirm the release key fingerprint and signed release sequence.
  4. Run the packaged installer, which verifies its signed release lock before activation.

Dataset

  1. Verify every downloaded part, then verify the assembled archive SHA-256.
  2. RC52 does not publish a replacement chain dataset.
  3. Keep the existing compatible native and EVM data in place for this update.
  4. Never merge database or freezer directories from different histories by hand.
curl -4 --http1.1 -fL --retry 12 --retry-all-errors -C - \
  "https://GATEWAY.example/ipfs/CID_FROM_RELEASE_MANIFEST" \
  -o "ARTIFACT.part"
printf '%s  %s\n' "SHA256_FROM_RELEASE_MANIFEST" "ARTIFACT.part" | sha256sum -c -

When an IPFS gateway times out

A gateway timeout does not change the CID or the file. Resume through another gateway and verify the final hash. If the IPFS page itself is unavailable, use the stable web copy.

1. Keep the partial fileDo not delete .part. The documented command resumes it with -C -.
2. Change the gatewayTry each gateway listed in the release manifest while keeping the same CID and output filename.
3. Force the stable transportKeep both -4 and --http1.1 on every large download.
4. Verify after assemblyTrust only the published SHA-256 and signature records, regardless of which gateway returned the bytes.
