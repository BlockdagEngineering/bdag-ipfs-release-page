Choose the deployment

  • All-in-one: node, pool, PostgreSQL and dashboard, with your own payout and ASIC configuration.
  • Node: Core plus Stack, with no pool, PostgreSQL, dashboard or ASIC requirement.
  • Pool: Pool plus Stack, connected to your explicitly configured compatible Core endpoint.
  • Dashboard: Dashboard plus Stack; monitoring is not authority for accepting blocks.

The explicit v2 CLI supports --mode all-in-one|node|pool|redis-dash. It needs owner-local configuration and service hooks; a component archive alone does not provision PostgreSQL or migrate an existing ledger.

Trust and upgrade boundaries

Owner-selected hashes establish byte integrity; native/EVM checks establish database coherence. A signature can identify a publisher, but no central signature, account, path name or numeric UID authorizes blockchain validity.

Pool53 is qualified here for a fresh empty database or an unchanged Pool53 reinstall against an independently verified compatible V2 database. Generic older-ledger upgrades and old-schema downgrades are not qualified. Preserve identity, payout, PostgreSQL history and your compatible rollback.

Historical documentation mentioning mandatory signatures or --allow-unsigned-catalog does not describe the explicit v2 deployment path. Do not use that obsolete flag.
